# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A single Claude agent skill (`heat-pump`) that sizes and troubleshoots residential air-to-water heat pump systems. It uses metric units and Croatian design temperatures. The repo is a Claude Code plugin and marketplace; the skill lives in `skills/heat-pump/`. There is no build step and there are no dependencies (Python standard library only).

## Commands

```bash
python3 skills/heat-pump/scripts/heat_calc.py selftest              # calculator unit tests: asserts the worked examples
python3 skills/heat-pump/scripts/heat_calc.py <subcommand> --help   # size, fabric, flow, modulation, volume, dhw, cities
claude plugin validate . --strict --profile directory                  # manifests + SKILL.md + plugin-directory submission checks
python3 ~/.claude/skills/skill-creator/scripts/quick_validate.py skills/heat-pump   # SKILL.md frontmatter rules (needs the skill-creator skill installed)
claude plugin eval . --allow-tools "Bash(python3:*)" --trust-plugin --no-publish -j 3   # end-to-end evals, with and without the plugin
claude plugin eval . --allow-tools "Bash(python3:*)" --trust-plugin --no-publish --case <name> --runs 1 --keep-temp   # one case, keeping its trace for debugging
claude --plugin-dir . -p "..."                                           # load the plugin in a session to check the skill triggers (shows as heat-pump:heat-pump)
```

Each `assert` in `selftest()` reproduces one worked example.

Eval notes:
- `--allow-tools "Bash(python3:*)"` lets the skill run `heat_calc.py`; without it, Claude does the arithmetic in its head. Granting Bash makes the eval require Claude Code's sandbox, which on Linux needs `bubblewrap` and `socat`. Without them every run is refused and scores 0.
- `--no-publish` keeps the report local; by default it's published to claude.ai. Reports go to `evals/results/` (gitignored).
- Per-run traces are deleted unless you pass `--keep-temp`. Kept dirs under `/tmp/claude-eval-*` are made read-only; `chmod -R u+rwx` before deleting them.
- With 3 runs per case and an LLM judge, the with-plugin score moves about ±0.1 between identical runs. Before changing the skill because of a failed grader, read the failing answer in `aggregate-result.json` (`cases[].arms.with[].graders[].evidence`): several past failures were grader wording, not skill errors.

## Architecture

The skill loads content in three levels, and each must stay consistent with the others:

1. **`SKILL.md` frontmatter `description`**: the only thing that decides whether the skill triggers. It must be ≤ 1024 chars with no `<` or `>` (the validator rejects them). The only allowed frontmatter keys are `name`, `description`, `license`, `allowed-tools`, `metadata` and `compatibility`.
2. **`SKILL.md` body**: the routing table (question type → reference file), the `heat_calc.py` subcommand table, the sizing and troubleshooting workflows, and the output templates. It also tells Claude to run each calculation as a standalone `python3 <base dir>/scripts/heat_calc.py …` command and read references with the Read tool. Keep that instruction: chained commands (`cd …; cat …; python3 …`) don't match `Bash(python3:*)` and were denied in the evals.
3. **`references/`**: the facts. `sizing.md` covers design temperature, heat loss, oversizing, COP/SCOP and DHW. `hydraulics.md` covers flow, pipes, underfloor circuits, buffers, volume and balancing. `troubleshooting.md` maps symptoms to causes. Files cross-reference each other by section number (e.g. `sizing.md §5`, `hydraulics.md §4`, `(§7)`), so renumbering sections breaks those links.

`skills/heat-pump/scripts/heat_calc.py` holds every number the skill computes with: the W/m² insulation table, the Croatian city design-temperature table, the radiator factor of 1.15, 45 L/person, 4.186 kJ/kgK and 0.33 W/m³K. The same values also appear in prose in `references/sizing.md` and in `SKILL.md`. If you change a value in one place, update the others and the matching `selftest` assertion.

`evals/<case>/` holds the `claude plugin eval` cases: `prompt.md` (the user prompt, plus `max_turns` and `allowed_tools`) and `graders/numbers.md` + `graders/advice.md` (LLM graders). The expected numbers in `numbers.md` were generated by running `heat_calc.py`, so regenerate them if the calculations change. Each grader passes only if every bullet holds, so keep bullets consistent with the references (e.g. the 180 L tank may round up to the standard 200 L, as `sizing.md §8` does).

**Releases:** `.github/workflows/release.yml` runs on `v*` tags. It fails unless the tag equals `v` + `plugin.json` `version`, runs `selftest`, zips `skills/heat-pump/` as `heat-pump.zip` (top-level `heat-pump/` folder, the layout Claude desktop/web skill upload expects) and creates the GitHub release with `gh`. The README links to `releases/latest/download/heat-pump.zip`, so keep that asset name.

`.claude-plugin/plugin.json` has no `skills` field, so the default `skills/` directory is used. Don't point it at `./`: `claude plugin eval` refuses to run when the skills path overlaps `evals/`. `marketplace.json` lists the same repo (`source: "./"`) so `/plugin install heat-pump --marketplace MarinX/heat-pump-skill` works. `plugin.json` `icon` points to `assets/icon.jpg`; the plugin directory wants a square PNG/JPEG, 512-2048 px per side, under 2 MB, and stores it only on the first submission.

## Content rules

- **No new domain information.** The skill content was built strictly from a fixed set of material: the calculator and the video series linked in the README. Don't add facts, thresholds or rules of thumb that aren't already in `references/`. If something is unclear or the sources conflict, ask the user instead of choosing. The skill itself tells Claude to say "not covered" rather than fill gaps.
- **No source attribution inside the skill files.** The calculator and videos are credited only in the README's References section. Keep `SKILL.md`, `references/`, `scripts/` and `evals/` free of source names, tags and phrasing like "the video says" or "the calculator's".
- **Known deliberate deviation:** `modulation` computes the cycling temperature as `t_in − min_output / (kW/K)` (≈10 °C in the 6.8 kW example). The original material said 8 °C, but that was an arithmetic slip. Keep the corrected maths.
- `size` rejects unknown cities, out-of-range area (20-500 m²) and out-of-range occupants (1-10) instead of silently defaulting.
